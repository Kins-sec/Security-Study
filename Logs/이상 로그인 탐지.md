# SSH 이상 로그인 탐지 실습

## 목적

Linux 서버의 SSH 인증 로그를 분석하여 로그인 성공 및 실패 이벤트를 확인하고, 반복적인 로그인 실패를 집계하여 이상 로그인 의심 이벤트를 판단하는 과정을 실습한다.

## 환경

- OS: Ubuntu Server 26.04

- Virtualization: VMware Workstation 17.6.4

- 접속 방식: Windows PowerShell SSH 및 VMware Ubuntu 터미널

- 분석 대상: SSH 인증 로그

# 1. SSH 로그인 로그 확인

## 명령어

sudo journalctl -u ssh


## 설명

journalctl 명령어를 사용하여 SSH 서비스에서 발생하는 인증 로그를 확인한다.

SSH 로그에는 사용자 로그인 성공 및 실패 기록이 저장되며, 이를 통해 서버에서 발생하는 인증 이벤트를 확인할 수 있다.

# 8. IP별 로그인 실패 횟수 집계

## 명령어

sudo journalctl -u ssh --since "30 minutes ago" | grep "Failed password" | awk '{print $(NF-3)}' | sort | uniq -c

## 설명

SSH 인증 로그에서 Failed password 메시지가 포함된 기록을 추출하고, 접속 IP 주소를 기준으로 실패 횟수를 집계한다.

grep: 로그인 실패 로그 추출

awk: 로그에서 접속 IP 주소 추출

sort: IP 주소 정렬

uniq -c: 동일한 IP 주소의 발생 횟수 집계

## 실행 결과

15 192.168.204.1

최근 30분 동안 192.168.204.1에서 총 15회의 로그인 실패가 발생한 것을 확인하였다.

# 9. 계정별 로그인 실패 횟수 집계

## 명령어

```bash
sudo journalctl -u ssh --since "30 minutes ago" | grep "Failed password" | awk '{for(i=1;i<=NF;i++) if($i=="user") print $(i+1); else if($i=="for" && $(i+1)!="invalid") print $(i+1)}' | sort | uniq -c
```

## 설명

로그에서 로그인 실패가 발생한 계정명을 추출하고 계정별 실패 횟수를 집계한다.

이를 통해 어떤 계정을 대상으로 로그인 실패가 반복되었는지 확인할 수 있다.

# 10. 이상 로그인 탐지 기준 설정

## 탐지 기준

이번 실습에서는 다음과 같은 기준을 설정하였다.

동일한 출발지 IP에서 5분 이내 SSH 로그인 실패가 5회 이상 발생하면 이상 로그인 의심 이벤트로 분류한다.

해당 기준은 학습을 위해 설정한 실습용 기준이며, 실제 운영 환경에서는 조직의 보안 정책과 정상적인 로그인 패턴을 고려하여 조정해야 한다.

## 명령어

sudo journalctl -u ssh --since "5 minutes ago" | grep "Failed password" | awk '{print $(NF-3)}' | sort | uniq -c

## 설명

최근 5분 동안 발생한 SSH 로그인 실패 기록을 조회하고 출발지 IP별 실패 횟수를 집계한다.

집계 결과를 앞서 설정한 탐지 기준과 비교하여 이상 로그인 의심 이벤트에 해당하는지 판단한다.

## 실행 결과

6 192.168.204.1

최근 5분 동안 192.168.204.1에서 총 6회의 로그인 실패가 발생하였다.

설정한 탐지 기준인 5회 이상을 초과하였으므로 이상 로그인 의심 이벤트로 분류하였다.

# 11. SSH 로그인 성공 기록 확인

## 명령어

sudo journalctl -u ssh --since "30 minutes ago" | grep -E "Accepted password|Accepted publickey"

## 설명

SSH 인증 로그에서 Accepted password 및 Accepted publickey 메시지를 확인하여 로그인 성공 기록을 조회한다.

로그인 실패 기록과 성공 기록을 구분하면 인증 결과를 파악하는 데 도움이 된다.

Accepted password: 비밀번호 인증 성공

Accepted publickey: 공개키 인증 성공

Failed password: 비밀번호 인증 실패

## 실행 결과

Nov 27 08:38:37 ubuntu sshd-session[2139]: Accepted password for kins from 192.168.204.1 port 52586 ssh2

kins 계정으로 SSH 비밀번호 인증에 성공한 기록을 확인하였다.

해당 성공 기록은 앞서 발생시킨 testuser 로그인 실패와 별개의 접속 기록이다.

# 12. 보안 관점

SSH는 Linux 서버를 원격으로 관리하기 위해 사용되는 서비스이며, 공격자가 비인가 접근을 시도할 수 있는 대상이다.

이번 실습을 통해 다음과 같은 보안 관점의 분석 방법을 확인하였다.

반복적인 로그인 실패는 Brute Force 공격 가능성을 나타낼 수 있다.

존재하지 않는 계정과 존재하는 계정의 인증 실패 로그는 서로 다른 형태로 기록된다.

동일한 IP에서 발생한 로그인 실패 횟수를 집계하여 반복적인 접근 시도를 파악할 수 있다.

일정 시간 동안의 로그인 실패 횟수를 기준으로 이상 로그인 의심 이벤트를 분류할 수 있다.

로그인 성공 및 실패 기록을 구분하여 인증 결과를 분석해야 한다.

실제 보안관제 환경에서는 로그 분석 결과를 바탕으로 관련 이벤트를 추가 확인하고, 보안 정책에 따라 접근 차단 등의 대응 조치를 검토할 수 있다.

# 실습 결과

Windows PowerShell에서 Ubuntu 서버로 SSH 접속을 시도하고, 존재하지 않는 계정과 존재하는 계정의 로그인 실패 이벤트를 각각 발생시켰다.

이후 SSH 인증 로그에서 Invalid user와 Failed password 메시지를 비교하고, IP별 및 계정별 로그인 실패 횟수를 집계하였다.

또한 5분 내 로그인 실패 5회 이상이라는 실습용 탐지 기준을 설정하고, 실제로 6회의 실패가 발생한 것을 확인하여 이상 로그인 의심 이벤트로 분류하였다.

마지막으로 SSH 로그인 성공 기록도 조회하여 인증 성공과 실패 로그의 차이를 확인하였다.

# 내가 학습한 점

이번 실습을 통해 SSH 로그인 로그에서 계정과 접속 IP, 인증 결과를 확인하는 방법을 익혔다.

특히 존재하지 않는 계정으로 접속했을 때는 Invalid user가 기록되고, 존재하는 계정에서 비밀번호 인증에 실패했을 때는 Failed password가 기록되는 차이를 확인했다.

또한 IP별 및 계정별 로그인 실패 횟수를 집계하고, 5분 내 5회 이상이라는 기준을 적용하여 반복적인 로그인 실패를 이상 로그인 의심 이벤트로 분류하는 과정을 실습했다.

이를 통해 보안관제에서는 단순히 로그인 실패 로그를 확인하는 것뿐만 아니라, 발생 시간과 접속 IP, 계정 및 실패 횟수를 함께 분석하는 것이 중요하다는 점을 배웠다.
이를 통해 SSH 로그 분석 방법과 보안관제 업무에서 필요한 이상 로그인 탐지 과정을 이해하였다.
