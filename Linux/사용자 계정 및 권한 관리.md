# Linux 사용자 계정 및 권한 관리

## 1. 실습 목적

Linux 서버에서 사용자 계정 정보를 확인하고, 그룹 및 관리자 권한을 관리하는 방법을 실습하였다.

또한 사용자 비밀번호 잠금 및 해제, 로그인 셸 변경, 시스템 로그 확인을 통해 계정 접근을 관리하는 기본적인 방법을 학습하였다.

## 2. 실습 환경

- OS: Ubuntu Server 26.04
- 가상화 프로그램: VMware Workstation 17.6.4
- 접속 방식: VMware 터미널 및 Windows PowerShell SSH 원격 접속

### 명령어 입력 방식

- 간단한 명령어는 VMware 우분투 터미널에서 직접 입력하였다.
- 길거나 복잡한 명령어는 오타 방지를 위해 Windows PowerShell에서 SSH로 원격 접속한 후 복사·붙여넣기 방식으로 입력하였다.

## 3. 사용자 계정 정보 확인

### 3-1. 사용자 계정 목록 확인

**사용 명령어**

```bash
tail /etc/passwd
```

`/etc/passwd` 파일에서 사용자 계정 정보를 확인하였다.

확인한 계정 정보:

```text
kins:x:1000:1000:kins:/home/kins:/bin/bash
testuser:x:1001:1001:,,,:/home/testuser:/bin/bash
```

**주요 항목**

| 항목 | 의미 |
|---|---|
| 사용자 이름 | 계정 이름 |
| x | 비밀번호 정보가 별도 파일에 저장됨을 의미 |
| UID | 사용자 식별 번호 |
| GID | 기본 그룹 식별 번호 |
| 사용자 정보 | 사용자 설명 정보 |
| 홈 디렉터리 | 사용자 개인 디렉터리 |
| 로그인 셸 | 로그인 시 사용하는 셸 |

비밀번호 해시 정보는 일반적으로 접근이 제한된 `/etc/shadow` 파일에서 관리된다.

**실습 중 발생한 오류**

처음에 `tail/etc/passwd`로 입력하여 다음 오류가 발생하였다.

```text
-bash: tail/etc/passwd: No such file or directory
```

명령어와 파일 경로 사이에 공백이 필요하다는 것을 확인하고 다음과 같이 수정하였다.

```bash
tail /etc/passwd
```

## 4. 사용자 관리자 권한 관리

### 4-1. sudo 그룹 추가

**사용 명령어**

```bash
sudo usermod -aG sudo testuser
```

`usermod` 명령어를 사용하여 `testuser`를 sudo 그룹에 추가하였다.

- `-a`: 기존 그룹을 유지하면서 추가
- `-G`: 추가할 그룹 지정
- `sudo`: 관리자 권한 사용과 관련된 그룹

## 5. 사용자 비밀번호 잠금 및 해제



## 6. 시스템 로그 확인

### 6-1. 최근 시스템 로그 확인

**사용 명령어**

```bash
sudo journalctl --since "10 minutes ago"
```

최근 10분간의 시스템 로그를 확인하였다.

로그에는 시스템 서비스 기록과 sudo 명령어 실행 기록 등이 포함되어 있었다.

### 6-2. 사용자 계정 변경 기록 검색

**사용 명령어**

```bash
sudo journalctl | grep usermod
```

시스템 로그 전체에서 `usermod`가 포함된 기록을 검색하였다.

**확인한 주요 로그**

```text
COMMAND=/usr/sbin/usermod -aG sudo testuser
usermod: add 'testuser' to group 'sudo'

COMMAND=/usr/sbin/usermod -L testuser
usermod: lock user 'testuser' password

COMMAND=/usr/sbin/usermod -U testuser
usermod: unlock user 'testuser' password
```

사용자 그룹 추가, 비밀번호 잠금 및 해제 작업이 로그에 기록되는 것을 확인하였다.

## 7. 사용자 로그인 셸 관리

### 7-1. 기존 로그인 셸 확인

**사용 명령어**

```bash
getent passwd testuser
```

**확인 결과**

```text
testuser:x:1001:1001:,,,:/home/testuser:/bin/bash
```

마지막 항목에서 `/bin/bash`가 설정된 것을 확인하였다.

`/bin/bash`는 일반적인 셸 로그인에 사용하는 프로그램이다.

### 7-2. 로그인 셸 변경 및 제한

**사용 명령어**

```bash
sudo usermod -s /usr/sbin/nologin testuser
```

`-s` 옵션을 사용하여 testuser의 로그인 셸을 `/usr/sbin/nologin`으로 변경하였다.

`nologin`은 일반적인 대화형 셸 로그인을 제한하는 데 사용된다.

## 8. 실습을 통해 학습한 점

이번 실습을 통해 Linux 서버의 사용자 계정 정보와 권한을 확인하고 변경하는 방법을 익혔다.

사용자가 어떤 그룹에 속해 있는지 확인하고, sudo 그룹을 추가하면 관리자 권한 사용 범위가 달라질 수 있다는 점을 알게 되었다.

또한 비밀번호 잠금과 해제, 로그인 셸 변경을 직접 진행하면서 계정 접근을 제한하는 방법을 학습하였다.

마지막으로 시스템 로그에서 계정 변경 기록을 검색하면서 서버에서 실행한 작업이 로그에 남는다는 것을 확인하였다.

## 9. 보안관제 업무와의 연관성

보안관제 업무에서는 서버 계정의 권한 변경이나 비정상적인 계정 사용이 보안 이벤트의 단서가 될 수 있다.

이번 실습에서 학습한 내용은 다음과 같은 업무와 연결된다.

사용자 계정 및 권한 변경 여부 확인

관리자 권한이 부여된 계정 확인

비밀번호 잠금 및 해제 기록 확인

시스템 로그를 통한 명령어 실행 기록 확인

계정의 로그인 설정 확인

실제 보안관제 환경에서는 이러한 기록을 다른 로그인 기록이나 보안 이벤트와 함께 분석하여 정상적인 관리 작업인지 의심스러운 행위인지 판단하는 것이 중요하다.

※ 이번 실습은 Ubuntu 개인 실습 환경에서 진행한 것으로, 실제 기업 보안관제 시스템 운영 경험은 아니다.
