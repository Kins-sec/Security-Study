# TCP 3-Way Handshake 실습

## 목적

Wireshark를 이용하여 TCP 연결 과정에서 발생하는 3-Way Handshake 패킷을 캡처하고 분석한다.

SYN, SYN + ACK, ACK 패킷의 역할과 통신 방향을 확인하여 TCP 연결이 수립되는 과정을 이해한다.

## 환경

- OS: Windows
- Tool: Wireshark 4.6.8
- Protocol: TCP

---

# 1. TCP 패킷 캡처

Wireshark를 실행한 후 현재 사용 중인 네트워크 인터페이스인 Ethernet을 선택하여 패킷 캡처를 시작한다.

TCP 패킷을 확인하기 위해 표시 필터에 다음 명령어를 입력한다.

```text
tcp
```

이후 웹사이트에 접속하여 새로운 TCP 연결을 발생시키고 관련 패킷을 확인한다.

## SYN 패킷 확인

SYN 비트가 설정된 패킷을 확인하기 위해 다음 필터를 사용한다.

```text
tcp.flags.syn == 1
```

이 필터는 SYN 비트가 설정된 패킷을 보여주므로 SYN 패킷과 SYN + ACK 패킷을 모두 확인할 수 있다.

연결을 요청하는 SYN 패킷만 확인하려면 다음 필터를 사용한다.

```text
tcp.flags.syn == 1 && tcp.flags.ack == 0
```

## 특정 서버 통신 확인

특정 서버와 주고받은 TCP 패킷만 확인하려면 다음 필터를 사용한다.

```text
ip.addr == 172.66.147.243 && tcp.port == 443
```

---

# 2. TCP 3-Way Handshake 분석

TCP는 데이터를 주고받기 전에 클라이언트와 서버 사이에 연결을 수립하는 과정을 거친다.

이때 SYN, SYN + ACK, ACK 순서로 총 3번의 패킷을 주고받는다.

① SYN

클라이언트가 서버에 TCP 연결을 요청하는 패킷이다.

② SYN + ACK

서버가 클라이언트의 연결 요청을 확인하고 연결 요청에 응답하는 패킷이다.

③ ACK

클라이언트가 서버의 응답을 확인하고 마지막 ACK 패킷을 전송한다.

이후 서버가 마지막 ACK를 받으면 TCP 연결이 수립된다.


실제 패킷에서는 다음과 같은 통신을 확인하였다.

```text
클라이언트 (192.168.219.100:50550)       서버 (172.66.147.243:443)

          |                                      |
          | ------------- SYN -----------------> |
          |                                      |
          | <---------- SYN + ACK ---------------|
          |                                      |
          | ------------- ACK -----------------> |
          |                                      |
          |              TCP 연결 수립            |
```

## 패킷 분석

### SYN

클라이언트인 192.168.219.100에서 서버 172.66.147.243의 443번 포트로 TCP 연결을 요청하는 SYN 패킷을 확인하였다.

### SYN + ACK

서버가 클라이언트의 연결 요청을 받은 후 SYN과 ACK를 함께 설정하여 응답하는 것을 확인하였다.

### ACK

클라이언트가 서버의 응답을 받은 후 마지막 ACK 패킷을 전송하는 것을 확인하였다.

이 과정이 완료되면 TCP 연결이 수립된다.

---

# 3. 보안 관점

TCP 3-Way Handshake는 네트워크 연결이 수립되는 기본 과정으로, 보안관제에서도 네트워크 패킷을 분석할 때 알아야 하는 개념이다.

예를 들어 SYN 패킷이 특정 서버로 비정상적으로 많이 발생하고 연결이 정상적으로 완료되지 않는다면 SYN Flood 공격을 의심할 수 있다.

SYN Flood는 공격자가 서버에 SYN 패킷을 대량으로 전송하여 연결 대기 상태를 증가시키고, 서버의 연결 처리 자원에 부담을 주는 공격이다.

따라서 보안관제에서는 SYN 패킷의 발생량과 통신 흐름을 확인하여 정상적인 연결인지 비정상적인 접근인지 분석하는 것이 중요하다.

---

# 4. 실습 결과

Wireshark를 이용하여 실제 TCP 패킷을 캡처하고 SYN, SYN + ACK, ACK 패킷을 분석하였다.

이를 통해 TCP 연결이 3-Way Handshake 과정을 거쳐 수립되는 것을 실제 패킷으로 확인하였다.

## 내가 학습한 점

이번 실습을 통해 TCP 연결은 단순히 데이터를 주고받는 것이 아니라, SYN, SYN + ACK, ACK 순서로 서로 연결을 확인하는 과정을 거친다는 것을 이해하였다.

또한 Wireshark에서 출발지와 목적지 IP, 포트 번호, TCP 플래그를 확인하면 패킷이 어떤 방향으로 이동하고 어떤 역할을 하는지 파악할 수 있다는 것을 배웠다.

보안관제 업무에서도 이러한 정상적인 통신 흐름을 이해하고 있어야 비정상적인 SYN 패킷이 반복적으로 발생하는 상황을 발견했을 때 SYN Flood와 같은 공격을 의심하고 분석할 수 있다는 점을 학습하였다.
