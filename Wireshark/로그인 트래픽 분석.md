# Wireshark를 이용한 웹 트래픽 분석 실습

## 목적

Wireshark를 이용하여 웹사이트 접속 과정에서 발생하는 네트워크 패킷을 캡처하고, 출발지 IP와 목적지 IP, 포트 번호, 프로토콜 등의 정보를 확인한다.

또한 HTTP와 HTTPS 통신의 차이를 이해하고, TLS 패킷 분석을 통해 암호화된 통신에서 확인할 수 있는 정보와 확인하기 어려운 정보를 알아본다.

## 환경

- Windows
- Wireshark 4.6.8
- Ethernet 네트워크 인터페이스

---

# 1. 네트워크 패킷 캡처

## 실습 방법

1. Wireshark를 실행한다.
2. 현재 사용 중인 네트워크 인터페이스인 Ethernet을 선택한다.
3. 패킷 캡처를 시작한다.
4. 브라우저에서 웹사이트에 접속하여 네트워크 통신을 발생시킨다.
5. 캡처를 중지하고 수집된 패킷을 확인한다.

웹사이트에 접속하면 내 컴퓨터와 웹 서버 사이에서 데이터를 주고받으며 다양한 네트워크 패킷이 발생한다.

캡처된 패킷을 통해 네트워크 통신이 이루어지는 과정을 확인한다.

# 2. 출발지 IP와 목적지 IP 확인

## 확인 방법

캡처된 패킷 목록에서 Source와 Destination 항목을 확인한다.

## 확인 내용

- Source: 패킷을 전송하는 출발지 IP 주소
- Destination: 패킷이 전달되는 목적지 IP 주소

# 3. 포트 번호와 프로토콜 확인

## 표시 필터

```text
tcp.port == 443
```

## 확인 내용

- 출발지 포트 번호
- 목적지 포트 번호
- 사용 프로토콜
- 패킷 정보

**그림 3. HTTPS 통신에 사용되는 포트 및 프로토콜 확인**

## 설명

표시 필터에 `tcp.port == 443`을 입력하여 TCP 443번 포트를 사용하는 패킷을 확인한다.

443번 포트는 일반적으로 HTTPS 통신에 사용된다.

패킷의 Protocol과 Info 항목을 함께 확인하여 통신에 사용된 프로토콜과 패킷 정보를 분석한다.

이번 실습에서는 TCP 443번 포트를 사용하는 HTTPS 통신을 중심으로 패킷을 확인하였다.

참고로 HTTP/3는 QUIC 프로토콜을 기반으로 하며 UDP 443번 포트를 사용할 수 있다.

# 4. HTTPS 암호화 통신 분석

HTTPS는 TLS를 이용하여 통신 데이터를 암호화한다. TLS 연결 과정에서 발생하는 핸드셰이크 패킷과 암호화된 데이터를 확인한다.

## 4-1. TLS Client Hello 확인

### 표시 필터

```text
tls.handshake.type == 1
```

### 확인 내용

- Client Hello
- 지원하는 TLS 버전
- 지원하는 암호화 방식

### 실행 결과

<img width="750" height="1022" alt="와이어샤크4" src="https://github.com/user-attachments/assets/9f638aa0-47ed-47a5-aac5-8e07d2dd42d4" />


**그림 4. TLS Client Hello 패킷 확인**

### 설명

표시 필터에 `tls.handshake.type == 1`을 입력하여 Client Hello 패킷을 확인한다.

Client Hello는 클라이언트가 서버와 TLS 연결을 시작하면서 지원하는 TLS 버전과 암호화 방식 등의 정보를 전달하는 메시지이다.

이를 통해 HTTPS 통신이 시작되는 TLS 핸드셰이크 과정을 확인한다.

## 4-2. TLS Server Hello 확인

### 표시 필터

```text
tls.handshake.type == 2
```

### 확인 내용

- Server Hello
- 선택된 TLS 버전
- 선택된 암호화 방식

**그림 5. TLS Server Hello 패킷 확인**

### 설명

표시 필터에 `tls.handshake.type == 2`를 입력하여 Server Hello 패킷을 확인한다.

Server Hello는 서버가 클라이언트의 연결 요청에 응답하면서 사용할 TLS 버전과 암호화 방식 등을 선택하여 전달하는 메시지이다.

이를 통해 TLS 핸드셰이크 과정에서 서버가 연결 설정에 참여하는 과정을 확인한다.

## 4-3. 암호화된 Application Data 확인

### 표시 필터

```text
tls.record.content_type == 23
```

### 확인 내용

- TLS Record Layer
- Content Type: Application Data (23)
- 암호화된 데이터

**그림 6. HTTPS 통신에서 암호화된 Application Data 확인**

### 설명

표시 필터에 `tls.record.content_type == 23`을 입력하여 Content Type이 23인 TLS 패킷을 확인한다.

패킷 상세 정보에서 TLS 1.2의 Application Data 항목을 확인하였다.

Application Data는 TLS 연결을 통해 전송되는 애플리케이션 데이터를 의미한다. HTTPS 통신에서는 해당 데이터가 암호화되어 전송되므로 일반적인 패킷 캡처만으로 실제 로그인 아이디나 비밀번호 등의 내용을 확인하기 어렵다.

다만 출발지와 목적지 IP, 포트 번호, 패킷 크기, 통신 시간 등의 네트워크 정보는 확인할 수 있다.

# 5. HTTP와 HTTPS의 차이

HTTP는 웹에서 데이터를 주고받는 프로토콜로, 통신 내용을 기본적으로 암호화하지 않는다.

반면 HTTPS는 TLS를 이용하여 통신 내용을 암호화하므로 데이터가 전송되는 과정에서 제3자가 내용을 쉽게 확인할 수 없도록 보호한다.

| 구분 | HTTP | HTTPS |
|---|---|---|
| 기본 포트 | 80 | 443 |
| 암호화 | 기본적으로 암호화하지 않음 | TLS를 이용해 암호화 |
| 데이터 확인 | 전송 내용이 노출될 수 있음 | 일반적인 패킷 캡처로 실제 내용 확인이 어려움 |

# 6. 보안 관점

네트워크 패킷 분석은 비정상적인 통신이나 의심스러운 네트워크 활동을 확인하는 데 활용할 수 있다.

보안관제 환경에서는 패킷 정보를 바탕으로 다음 항목을 분석할 수 있다.

- 출발지 및 목적지 IP 확인
- 비정상적인 포트 사용 여부 확인
- 통신 프로토콜 확인
- 의심스러운 네트워크 통신 분석
- 암호화된 통신의 연결 정보 및 패킷 흐름 확인

암호화된 통신은 실제 데이터 내용을 직접 확인하기 어렵기 때문에 IP, 포트, 통신 시간, 패킷 크기 등의 정보를 함께 분석하는 것이 중요하다.

# 7. 실습 결과

Wireshark를 이용하여 웹사이트 접속 과정에서 발생하는 네트워크 패킷을 캡처하고, 출발지와 목적지 IP, 포트 번호, 프로토콜 등의 정보를 확인하였다.

또한 TLS Client Hello와 Server Hello 패킷을 통해 TLS 핸드셰이크 과정을 이해하고, Application Data 패킷을 확인하여 HTTPS 통신에서 데이터가 암호화되어 전송되는 특징을 확인하였다.

이를 통해 암호화된 통신에서도 IP 주소, 포트 번호, 패킷 크기 등 네트워크 정보를 확인할 수 있으며, 이러한 정보를 바탕으로 통신 흐름을 분석할 수 있다는 점을 학습하였다.
